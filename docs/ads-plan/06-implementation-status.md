## 1. ما الذي أُنجِز؟

وحدة إعلانات عاملة بالكامل، مدمجة في المكدّس الحالي (Express + SQLite + JWT + React)، تشمل:

- **حساب المعلِن:** ترقية أي مستخدم إلى معلِن بنقرة (`POST /api/ads/advertisers`) مع إعادة إصدار رمز JWT بالدور الجديد.
- **المحفظة:** شحن فوري يعمل **بدون Stripe** (وضع تجريبي)، ومسار Stripe Checkout حقيقي عند توفّر المفاتيح، مع دفتر قيود (Ledger).
- **الحملات:** إنشاء حملة + إبداع في نداء واحد، جدولة الحالة، إطلاق/إيقاف/استئناف.
- **محرّك التوزيع:** `GET /api/ads/serve` — ترشيح أهلية + ترتيب بـ eCPM + اختيار الفائز + إرجاع رموز تتبّع موقّعة.
- **التتبّع:** `POST /api/ads/events` للظهور والنقر، بأحداث موقّعة (لا يُحتسب أي حدث برمز مزوّر)، وخصم التكلفة **خادمياً** ضمن معاملة ذرّية.
- **التقارير:** أداء لكل حملة + الإجماليات (`GET /api/ads/reports`).
- **الإدارة:** طابور مراجعة + اعتماد/رفض + لوحة إيراد (`/api/ads/admin/*`).
- **إعلانات «المنزل» (House Ads):** ثلاث حملات افتراضية للمنصة تُبذَر تلقائياً فتظهر الإعلانات حيّة من أول تحميل.
- **الواجهة:** لوحة معلِن (حملات/إنشاء بمعاينة حيّة/محفظة/تقارير)، لوحة مدير، ومكوّن `AdSlot` مدمج في لوحة التحكّم وقائمة المتداولين — متعدّد اللغات (en/ar كاملتان، والبقية ترث الإنجليزية) وداعم لـ RTL.

## 3. متغيّرات البيئة

| المتغيّر | الافتراضي | الأثر |
|---|---|---|
| `ADMIN_EMAILS` | — | قائمة إيميلات (مفصولة بفواصل) تُمنح دور `admin` للوصول إلى لوحة الإدارة |
| `ADS_AUTO_APPROVE` | `true` | اعتماد الحملات تلقائياً عند الإطلاق (لتجربة سلسة). **في الإنتاج اضبطه `false`** لتفعيل المراجعة البشرية الإلزامية للإعلانات المالية |
| `STRIPE_SECRET_KEY` | — | عند توفّره يُستخدم Stripe Checkout للشحن؛ بدونه يعمل الشحن بوضع تجريبي فوري |
| `JWT_SECRET` | `dev-secret-change-me` | توقيع الرموز ورموز الأحداث |

## 4. التشغيل والتجربة محلياً

```bash
# من جذر المشروع
npm run install:all      # تثبيت اعتماديات الجذر + client + server
npm run dev              # تشغيل الخادم (3001) والواجهة (3000) معاً
```

**تدفّق التجربة (Happy Path):**
1. سجّل حساباً جديداً وادخل.
2. لاحظ ظهور بانر «مُموّل» في لوحة التحكّم وبطاقة أصيلة في قائمة المتداولين (إعلانات المنزل).
3. افتح **الإعلانات** من القائمة ← أنشئ حساب معلِن (نقرة واحدة).
4. **المحفظة** ← اشحن 100$ (يُضاف فوراً في الوضع التجريبي).
5. **إنشاء** ← املأ الحملة وشاهد المعاينة الحيّة ← «إرسال وإطلاق».
6. عُد إلى لوحة التحكّم ← سيظهر إعلانك (يفوز على إعلانات المنزل لأن مزايدته > 0).
7. **التقارير** ← تابع الظهور/النقرات/الإنفاق لحظياً.
8. لتجربة الإدارة: شغّل الخادم بـ `ADMIN_EMAILS=بريدك` ثم ادخل بذلك الحساب ← ستظهر **إدارة الإعلانات**.

> تم التحقّق من هذا التدفّق كاملاً (تسجيل ← معلِن ← شحن ← حملة ← إطلاق ← عرض ← حدث ← خصم ← تقرير ← إدارة)،
> إضافةً إلى اختبارات أمنية: حجب الأدوار (403)، ورفض رموز الأحداث المزوّرة، وحساب التكلفة خادمياً.

## 5. ما الذي أُجِّل للمراحل اللاحقة؟

متوافق مع خارطة الطريق في [الوثيقة 05](./05-security-compliance-and-roadmap.md):

- مزاد تنافسي (GSP) متعدّد المزايدين، ونموذج CPA وتتبّع التحويلات.
- إعادة الاستهداف والجماهير المخصّصة، والتحسين الآلي بالذكاء الاصطناعي.
- حدّ التكرار/الوتيرة المتقدّمان، وتجميع البيانات الدوري (Rollup) إلى `ad_daily_stats`.
- الهجرة إلى PostgreSQL + Redis، وتخزين صور الإبداعات على CDN.
- رفع الصور للإبداعات (الحالي يعتمد على نص/لون مميّز).
