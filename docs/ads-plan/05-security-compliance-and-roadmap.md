## 1. الأمان (Security) {#1-security}

### 1.1 التحكّم في الوصول (Authorization)

- كل مسارات `/api/ads/*` خلف `requireAuth`؛ ومسارات المعلِن/المدير خلف `requireRole`.
- **عزل المُلكية:** المعلِن يصل إلى موارده فقط — `advertiser_id` يُشتقّ من JWT، **لا** من جسم الطلب أو
  معاملات الاستعلام (لمنع الوصول الأفقي IDOR).
- مسار التوزيع `/ads/serve` عام لكنه لا يكشف أي بيانات شخصية، ويقبل سياقاً مُصرّحاً به فقط.

### 1.2 سلامة الأحداث والمال

| الخطر | الإجراء المضادّ |
|---|---|
| تزوير الظهور/النقر | رموز موقّعة من الخادم بانتهاء صلاحية (انظر [04 §4.2](./04-targeting-billing-and-analytics.md#4-tracking)) |
| تلاعب بالتكلفة | التكلفة تُحسب في الخادم حصراً |
| رصيد سالب / سباق | خصم داخل معاملة ذرّية، ومنع الرصيد السالب |
| تكرار Webhook الدفع | مفتاح Idempotency + التحقّق من توقيع Stripe |
| إساءة معدّل الطلبات | حدّ معدّل على `/ads/serve` و`/ads/events` |

### 1.3 أمان المدخلات والمحتوى

- التحقّق من رابط الهبوط (Landing URL): مخطّط `https` فقط، قائمة حظر، تطبيع لمنع SSRF/إعادة توجيه خبيث.
- رفع الصور: التحقّق من النوع والحجم والأبعاد، وفحص المحتوى، والتخزين خارج جذر التطبيق (وعلى CDN لاحقاً).
- التحقّق من القيم العددية (ميزانيات، مزايدات) ومنع القيم السالبة/الشاذّة.

### 1.4 قائمة تدقيق أمنية (Checklist)

- [ ] `requireRole` على كل مسارات المعلِن/المدير.
- [ ] عزل المُلكية بـ `advertiser_id` من الرمز.
- [ ] رموز أحداث موقّعة وذات انتهاء صلاحية.
- [ ] التكلفة محسوبة خادمياً + خصم ذرّي بلا رصيد سالب.
- [ ] التحقّق من توقيع Stripe + Idempotency.
- [ ] التحقّق من روابط الهبوط ورفع الصور.
- [ ] حدود معدّل على مساري العرض والأحداث.
- [ ] تسجيل تدقيق (Audit) لقرارات الاعتدال والتعديلات المالية.

## 2. اعتدال المحتوى وسياسة الإعلانات {#2-moderation}

### 2.1 تصنيف السياسة

| الفئة | أمثلة | القرار |
|---|---|---|
| **محظور (Prohibited)** | ضمان أرباح، «بلا مخاطرة»، مخططات احتيالية، خدمات مالية غير مرخّصة | رفض |
| **مقيّد (Restricted)** | منتجات مالية/CFD/فوركس، عملات رقمية، خدمات إشارات | مسموح **بشروط**: تنبيه مخاطر + إثبات ترخيص + قيود ولاية قضائية |
| **مسموح (Allowed)** | أدوات تعليمية عامة، برمجيات، محتوى غير مضلّل | مراجعة معتادة |

### 2.2 سير عمل الاعتدال

```
MVP:    مراجعة بشرية لكل إبداع قبل النشر (طابور المدير) + تسجيل القرار والسبب.
لاحقاً: فحص آلي مسبق (AI Pre-screen بـ Claude) يرشّح المخالفات الواضحة ويختصر طابور البشر.
```

كل قرار اعتدال يُسجَّل في `moderation_log` (المدير، الإجراء، السبب، الوقت) لأغراض التدقيق والمساءلة.

### 2.3 الإفصاحات الإلزامية

- وسم «**مُموّل / Sponsored**» ظاهر على كل إعلان.
- **تنبيه مخاطر إلزامي** على كل إعلان مالي (مثال: «تداول العقود مقابل الفروقات ينطوي على مخاطر عالية
  لخسارة رأس المال»)، بصياغة تُراجَع قانونياً وتُترجَم لكل لغة.

## 3. الامتثال التنظيمي للإعلانات المالية {#3-compliance}

> ⚠️ **هذا المحور حاسم.** بما أن المنصة في مجال التداول، فإن الإعلانات المعروضة غالباً **مالية**،
> وتخضع لتنظيم صارم. الإخفاق هنا يحمل مخاطر قانونية وسمعية تفوق أي مكسب إعلاني.

### 3.1 المبادئ العامة

تتبنّى السياسة قاعدة «**عادل، واضح، غير مضلّل (Fair, Clear, Not Misleading)**»:
- منع ادّعاءات العائد المضمون أو إبراز الأرباح دون إبراز المخاطر بالتوازن نفسه.
- إلزام تنبيهات المخاطر الظاهرة وغير المطموسة.
- منع استهداف الفئات الهشّة بمنتجات عالية المخاطر.

### 3.2 ضوابط عملية

| الضابط | التطبيق |
|---|---|
| التحقّق من ترخيص المعلِن | للفئات المقيّدة: طلب إثبات ترخيص/تنظيم قبل التفعيل |
| قيود الولاية القضائية | منع عرض إعلانات منتجات معيّنة في دول محظورة (استهداف عكسي إلزامي) |
| تنبيه المخاطر | إلزامي ومُدمج في قالب الإبداع المالي، غير قابل للإزالة |
| سجلّ الامتثال | حفظ نسخة الإعلان وقرار الاعتماد وتاريخه (للمراجعة التنظيمية) |

### 3.3 إخلاء مسؤولية

هذه الوثيقة **ليست استشارة قانونية**. المتطلّبات تختلف حسب الأسواق المستهدفة (مثل أطر FCA/ESMA
للعقود مقابل الفروقات في أوروبا، وأطر أخرى إقليمياً). يجب إشراك مستشار قانوني متخصّص لكل سوق قبل
إطلاق الإعلانات المالية فيه، وتحويل مخرجاته إلى قواعد سياسة قابلة للتنفيذ في النظام.

## 4. الخصوصية وحماية البيانات {#4-privacy}

| المبدأ | التطبيق |
|---|---|
| **الموافقة (Consent)** | الاستهداف السلوكي والمخصّص يتطلّب موافقة صريحة؛ مع خيار **إيقاف الإعلانات المخصّصة** (Opt-out) يعود لإعلانات سياقية فقط |
| **الأساس القانوني** | تحديد الأساس لكل معالجة (موافقة/مصلحة مشروعة) |
| **تقليل البيانات** | الاستهداف داخلي؛ لا تصدير بيانات شخصية للمعلِن؛ تعميم الإشارات الحسّاسة (شريحة رصيد لا قيمة خام) |
| **حقوق الأفراد** | الوصول/التصحيح/الحذف؛ وحذف/إخفاء هوية أحداث الإعلانات عند الطلب |
| **الاحتفاظ (Retention)** | سياسة احتفاظ لأحداث `ad_events` (مثلاً تفصيل لفترة ثم تجميع/أرشفة) |
| **عدم التتبّع** | احترام إشارات Do-Not-Track حيثما أمكن |

## 5. خارطة الطريق وخطة التنفيذ {#5-roadmap}

```mermaid
graph LR
    P0["المرحلة 0\nالأساسات"] --> P1["المرحلة 1\nMVP عرض الإعلانات"]
    P1 --> P2["المرحلة 2\nالتعمّق"]
    P2 --> P3["المرحلة 3\nالتوسّع والذكاء"]
    P3 --> P4["المرحلة 4\nالنضج"]
```

### المرحلة 0 — الأساسات (Foundations)
- إضافة عمود `role` وتوسيع JWT و`requireRole`.
- كيان المعلِن (`advertisers`) + جداول المخطّط الأساسية.
- محفظة + شحن عبر Stripe (إعادة استخدام نمط الاشتراكات) + دفتر القيود.
- **الجهد التقديري:** ~1–2 أسبوع.

### المرحلة 1 — MVP عرض الإعلانات
- حملة واحدة (بانر + Native)، تسعير CPC/CPM، استهداف يدوي (دولة/لغة/خطة/اهتمام).
- محرّك توزيع مبسّط، مكوّن `AdSlot` في `Dashboard` و`TradersPage`.
- تتبّع ظهور/نقر بأحداث موقّعة، خصم آلي، لوحة معلِن أساسية، طابور مراجعة المدير.
- تنبيه مخاطر إلزامي + سياسة محتوى مبدئية.
- **الجهد التقديري:** ~3–5 أسابيع.

### المرحلة 2 — التعمّق
- CPA وتتبّع التحويلات، حدّ التكرار والوتيرة، أماكن عرض إضافية.
- تقارير مالية وكشوف حساب، توليد نصوص إبداعات بالذكاء الاصطناعي.
- فحص اعتدال آلي مسبق.
- **الجهد التقديري:** ~4–6 أسابيع.

### المرحلة 3 — التوسّع والذكاء
- مزاد تنافسي (GSP)، إعادة استهداف وجماهير مخصّصة، تحسين آلي وكشف شذوذ.
- هجرة `ad_events` إلى PostgreSQL + Redis للعدّادات + طابور كتابة الأحداث.
- واجهة API للمعلنين.
- **الجهد التقديري:** ~6–10 أسابيع.

### المرحلة 4 — النضج
- طلب برمجي خارجي (Programmatic)، أتمتة امتثال متقدّمة، تعدّد المناطق، CDN للإبداعات.

### الفريق المقترح
مطوّر Full-stack (Node/React) أساسي، بمساندة من: مصمّم منتج/UX، ومسؤول عمليات/اعتدال، ومستشار
قانوني (للإعلانات المالية) عند المرحلة 1 فما بعد.

## 6. المخاطر والتخفيف {#6-risks}

| الخطر | الأثر | التخفيف |
|---|---|---|
| تدهور تجربة المستخدم من الإعلانات | تخلّي المستخدمين | حدود كثافة صارمة، صلة عالية، حارس تجربة ضمن KPIs |
| مخالفة تنظيم الإعلانات المالية | مخاطر قانونية/سمعية | مراجعة بشرية، تنبيهات مخاطر، تحقّق ترخيص، استشارة قانونية |
| احتيال النقر/الظهور (IVT) | استنزاف ميزانيات المعلنين وفقدان الثقة | رموز موقّعة، إزالة تكرار، حدود معدّل، استرداد |
| ضعف معدّل الملء في البداية | مخزون مهدور | إعلانات «المنزل» (House Ads) الافتراضية + ترويج المتداولين المموّلين |
| خصوصية البيانات السلوكية | مخاطر امتثال | موافقة صريحة، تعميم الإشارات، عدم تصدير بيانات شخصية |
| حمل أحداث العرض على SQLite | تدهور أداء | تجميع دوري + مسار هجرة مبكر إلى PostgreSQL |
| تعقيد المزاد المبكر | تأخّر التسليم | البدء بترتيب eCPM مبسّط، تأجيل GSP |

## 7. معايير القبول لكل مرحلة (Definition of Done) {#7-acceptance}

**المرحلة 0:**
- [ ] يمكن ترقية مستخدم إلى معلِن، وشحن محفظته عبر Stripe، وانعكاس الرصيد في الدفتر.
- [ ] `requireRole` يمنع الوصول غير المصرّح به (مغطّى باختبارات).

**المرحلة 1:**
- [ ] معلِن ينشئ حملة وإبداعاً، يرسلها، يعتمدها المدير، فتُعرض فعلياً في مكان عرض.
- [ ] الظهور والنقر يُسجَّلان بأحداث موقّعة، ويُخصم الإنفاق ذرّياً، ويُوقَف عند نفاد الرصيد.
- [ ] لوحة المعلِن تعرض ظهور/نقرات/CTR/إنفاق بدقّة مطابقة للأحداث.
- [ ] كل إعلان مالي يحمل تنبيه مخاطر، وفشل المحرّك لا يُعطّل المنصة (فتحة فارغة).

**المرحلة 2:**
- [ ] التحويلات تُتتبَّع وتظهر CPA؛ حدّ التكرار يمنع تكرار الإعلان فوق العتبة.
- [ ] كشوف حساب مالية صحيحة قابلة للتصدير.

**المرحلة 3:**
- [ ] المزاد يختار الفائز بسعر ثانٍ صحيح؛ الأداء ضمن ميزانية الكمون بعد الهجرة.
