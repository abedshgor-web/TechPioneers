## الملخّص التنفيذي

هذه الوثيقة تُخطّط لبناء **نظام إعلانات تجارية** يُدمَج كوحدة (Module) داخل منصة TechPioneers الحالية
(تطبيق CopyTrade Pro لنسخ التداول). الهدف: تمكين **المعلنين** — وسطاء (Brokers)، شركات التمويل
الذاتي (Prop Firms)، مزوّدي أدوات وإشارات التداول، المنصات التعليمية، والمتداولين الراغبين في الترويج
لملفاتهم — من إطلاق **حملات إعلانية مستهدفة ومدفوعة** (بنموذج الدفع لكل نقرة CPC، أو لكل ألف ظهور CPM،
أو لكل تحويل CPA)، تُعرَض لمستخدمي المنصة في أماكن عرض محدّدة، مع لوحة تحكّم ذاتية الخدمة للمعلن،
ومحرّك استهداف، ونظام محفظة وتسوية مالية عبر Stripe، وتقارير وتحليلات، وتحسين مدعوم بالذكاء الاصطناعي،
ومراجعة إدارية تلتزم بضوابط الإعلانات المالية.

### لماذا «وحدة مدمجة» وليست نظاماً مستقلاً؟

| السبب | الأثر |
|---|---|
| **إعادة استخدام البنية الحالية** | مصادقة JWT، جدول المستخدمين، تكامل Stripe، نظام i18n، ومكوّنات React جاهزة — تقليل زمن التسليم. |
| **تحقيق الدخل من الجمهور القائم** | تحويل قاعدة المستخدمين الحالية إلى مصدر دخل إعلاني دون اكتساب جمهور جديد. |
| **بيانات الطرف الأول (First-party Data)** | المنصة تعرف سلوك المستخدم (المتداولون المتابَعون، الاستراتيجيات المفضّلة، مستوى المخاطرة) — وهي إشارات استهداف عالية القيمة لا تملكها الشبكات الخارجية. |
| **اتساق التجربة** | واجهة واحدة، لغة واحدة (8 لغات مدعومة)، وهوية بصرية موحّدة. |

## القرارات المعمارية الكبرى (ملخّص)

| القرار | الاختيار | المبرّر |
|---|---|---|
| **نمط الدمج** | وحدة داخل التطبيق الحالي (Modular within Express monolith) | سرعة التسليم، إعادة استخدام البنية، قابلية الفصل لاحقاً |
| **قاعدة البيانات** | SQLite الآن (better-sqlite3) → PostgreSQL عند الحجم | البدء بما هو قائم، الترقية عند ارتفاع حجم أحداث العرض |
| **نموذج التسعير الأولي** | CPC و CPM (يُضاف CPA لاحقاً) | الأبسط تنفيذاً والأكثر شيوعاً للبداية |
| **نموذج الدفع** | محفظة مسبقة الدفع (Prepaid Wallet) + شحن عبر Stripe | يناسب طبيعة الإنفاق الإعلاني المتغيّر، يحمي المنصة من الديون |
| **محرّك التوزيع** | ترشيح أهلية → ترتيب بـ eCPM (مزاد سعر ثانٍ لاحقاً) | بساطة MVP مع مسار ترقية واضح |
| **الأدوار** | إضافة `role` (user / advertiser / admin) إلى المستخدمين + توسيع JWT | لا توجد أدوار حالياً؛ مطلوبة لفصل صلاحيات المعلن والمدير |
| **التتبّع** | أحداث موقّعة من الخادم (Signed Events) + تجميع دوري (Rollup) | منع التزوير، وفصل مسار الكتابة الثقيل عن مسار التقارير |
| **التحسين الذكي** | Claude (Haiku للمهام البسيطة، Sonnet للجودة) | اتساقاً مع توجّه منصة TechPioneers في وثائق الـ CRM |

## المصطلحات (Glossary)

| المصطلح | التعريف |
|---|---|
| **المعلِن (Advertiser)** | كيان (مرتبط بحساب مستخدم) يُنشئ حملات ويموّلها ويدفع مقابل عرضها. |
| **الحملة (Campaign)** | الحاوية العليا: هدف، نموذج تسعير، ميزانية، جدول زمني. |
| **المجموعة الإعلانية (Ad Set)** | داخل الحملة: تحدّد الاستهداف والمزايدة وحدّ التكرار. |
| **الإبداع (Creative)** | الإعلان الفعلي المعروض: صورة/عنوان/نص/زر CTA/رابط هبوط، بنسخة لكل لغة. |
| **مكان العرض (Placement / Slot)** | موضع في الواجهة يُعرض فيه الإعلان (بانر اللوحة، بطاقة ضمن قائمة المتداولين... إلخ). |
| **الظهور (Impression)** | عرض الإعلان للمستخدم (ويُحتسب «القابل للمشاهدة» Viewable عند تحقّق شرط الرؤية). |
| **النقرة (Click)** | تفاعل المستخدم بالنقر على الإعلان. |
| **التحويل (Conversion)** | إجراء مرغوب بعد النقر (تسجيل، إيداع... عبر Postback/Pixel). |
| **CTR** | نسبة النقر إلى الظهور = Clicks / Impressions. |
| **CPC / CPM / CPA** | تكلفة النقرة / تكلفة الألف ظهور / تكلفة التحويل. |
| **eCPM** | العائد الفعّال لكل ألف ظهور — وحدة موحّدة للمقارنة بين الإعلانات في المزاد. |
| **معدّل الملء (Fill Rate)** | نسبة طلبات العرض التي عُرض فيها إعلان فعلي. |
| **المزايدة (Bid)** | المبلغ الذي يرغب المعلن بدفعه لكل نقرة/ظهور. |
| **المزاد (Auction)** | آلية اختيار الإعلان الفائز لكل طلب عرض. |
| **المحفظة (Wallet)** | رصيد المعلن المسبق الدفع الذي يُخصم منه الإنفاق. |
| **محرّك التوزيع (Ad Server)** | المكوّن الذي يختار الإعلان المناسب لكل طلب عرض ويعيد بيانات التتبّع. |
| **IVT** | حركة المرور غير الصالحة (Invalid Traffic) — نقرات/ظهور احتيالية أو آلية. |

## نطاق MVP (نظرة سريعة)

**ضمن النطاق:** تسجيل المعلن، حملة واحدة (بانر + بطاقة أصيلة Native)، تسعير CPC/CPM، استهداف يدوي
(الدولة، اللغة، الخطة، الاهتمام السلوكي)، شحن المحفظة عبر Stripe، تتبّع الظهور والنقر، لوحة تقارير
أساسية للمعلن، طابور مراجعة واعتماد للمدير، إلزامية تنبيه المخاطر على الإعلانات المالية.

**خارج نطاق MVP (مراحل لاحقة):** المزاد التنافسي متعدّد المزايدين، CPA/التحويلات، إعادة الاستهداف
والجماهير المخصّصة، التحسين الآلي بالذكاء الاصطناعي، واجهة API للمعلنين، الهجرة إلى PostgreSQL/Redis،
الطلب البرمجي الخارجي (Programmatic).
