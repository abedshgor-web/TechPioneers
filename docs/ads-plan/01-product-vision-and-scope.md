## 1. الغرض والرؤية {#1-purpose}

### 1.1 الغرض

بناء **منصة إعلانات تجارية** — أي نظام يتيح لجهات خارجية (معلنين) الدفع مقابل عرض رسائلهم التسويقية
لمستخدمي منصة TechPioneers. هذا يختلف عن «الإشعارات الداخلية» أو «الإعلانات المبوّبة الشخصية»: هنا
المنصة تلعب دور **الناشر (Publisher)** الذي يبيع مساحات عرض موجّهة، والمعلن يدفع، والمستخدم النهائي
يرى إعلانات مُختارة بعناية وذات صلة بسياق التداول.

### 1.2 الرؤية

> «أن نحوّل جمهور TechPioneers المتفاعل مع التداول إلى قناة إعلانية عالية الصلة، تُمكّن المعلنين الماليين
> من الوصول الدقيق، وتمنح المنصة مصدر دخل مستداماً، دون المساس بجودة تجربة المستخدم أو الثقة.»

### 1.3 السياق: لماذا الآن؟

منصة CopyTrade Pro تمتلك بالفعل: قاعدة مستخدمين مصادَق عليها، بيانات سلوكية غنية (متابعة المتداولين،
الاستراتيجيات، مستوى المخاطرة)، تكامل دفع (Stripe)، وواجهة متعدّدة اللغات. هذه الأصول مجتمعة تجعل بناء
طبقة إعلانية **إضافة تدريجية منخفضة التكلفة** بدل مشروع منفصل.

## 2. الجمهور والشخصيات (Personas) {#2-personas}

النظام يخدم **ثلاثة أطراف** لكلٍّ منها واجهة وأهداف مختلفة:

### 2.1 المعلِن (Advertiser)

الفئات المستهدفة في سياق منصة تداول:

| الفئة | مثال على ما يُعلن عنه |
|---|---|
| الوسطاء (Brokers) | فتح حساب تداول، عروض السبريد المنخفض، مكافآت الإيداع |
| شركات التمويل الذاتي (Prop Firms) | تحدّيات التمويل، برامج المتداول الممول |
| مزوّدو الأدوات والإشارات | مؤشّرات، روبوتات تداول (EA)، خدمات إشارات |
| المنصات التعليمية | دورات تداول، ندوات، اشتراكات تحليل |
| المتداولون (Sponsored) | الترويج لملف المتداول لزيادة المتابعين والنسخ |

**الشخصية المرجعية — «سارة، مديرة تسويق في وسيط»:**
- **الأهداف:** الوصول لمتداولين نشطين، تعظيم العائد على الإنفاق الإعلاني (ROAS)، قياس النتائج بدقّة.
- **نقاط الألم:** الشبكات العامة غير دقيقة في استهداف المتداولين؛ صعوبة قياس جودة الزيارة.
- **الاحتياجات:** استهداف دقيق حسب سلوك التداول، لوحة ذاتية الخدمة، تقارير واضحة، شفافية الإنفاق.

### 2.2 مدير المنصة / فريق العمليات (Admin / Ops)

- **الأهداف:** تعظيم دخل الإعلانات، حماية تجربة المستخدم، ضمان امتثال المحتوى الإعلاني (خصوصاً المالي).
- **نقاط الألم:** مخاطر قانونية من إعلانات مالية مضلّلة؛ خطر تدهور تجربة المستخدم من كثافة الإعلانات.
- **الاحتياجات:** طابور مراجعة واعتماد، أدوات سياسة المحتوى، لوحة دخل ومعدّل ملء، ضبط أماكن العرض.

### 2.3 المستخدم النهائي (Trader / Copier)

- **الأهداف:** استخدام المنصة لنسخ المتداولين دون إزعاج.
- **نقاط الألم:** الإعلانات المتطفّلة أو غير ذات الصلة تُفسد التجربة وتقلّل الثقة.
- **الاحتياجات:** إعلانات قليلة، ذات صلة، واضحة التمييز («مُموّل/Sponsored»)، مع خيار التحكّم في
  التخصيص (Opt-out من الإعلانات المخصّصة).

## 3. نموذج العمل وتحقيق الدخل {#3-business-model}

### 3.1 الدور الاقتصادي

المنصة = **الناشر (Publisher)** الذي يملك المخزون الإعلاني (Inventory) = أماكن العرض × عدد المستخدمين
× عدد الجلسات. الدخل = إجمالي إنفاق المعلنين على هذا المخزون.

```
الإيراد الإعلاني = عدد الظهور المباع × eCPM / 1000
              أو = عدد النقرات × متوسط CPC
```

### 3.2 نماذج التسعير

| النموذج | المعلِن يدفع مقابل | الأنسب لـ |
|---|---|---|
| **CPM** (تكلفة الألف ظهور) | كل 1000 ظهور | حملات الوعي بالعلامة (Brand Awareness) |
| **CPC** (تكلفة النقرة) | كل نقرة | حملات الأداء (جلب زيارات) |
| **CPA** (تكلفة التحويل) — لاحقاً | كل تحويل مكتمل | حملات الاكتساب (تسجيل/إيداع) |

### 3.3 مصادر دخل تكميلية (مراحل لاحقة)

- **المتداولون المموّلون (Sponsored Traders):** ترويج مدفوع لملفات المتداولين داخل قائمة الاكتشاف،
  مع إمكانية اقتسام الإيراد (Revenue Share).
- **العروض الحصرية (Premium Placements):** أماكن عرض مميّزة بسعر أرضي (Floor Price) أعلى.
- **حِزَم المعلنين (Packages):** التزامات إنفاق شهرية مقابل أولوية أو خصومات.

### 3.4 العلاقة بنظام الاشتراك الحالي

نظام الإعلانات **مستقل مالياً** عن اشتراك `free/pro` الحالي للمستخدمين، لكنه يتكامل معه بوجهين:
1. **إشارة استهداف:** خطة المستخدم (free/pro) تُستخدم كإشارة استهداف (مثلاً: استهداف مستخدمي free فقط).
2. **حدّ كثافة الإعلانات:** يمكن تقليل أو إلغاء الإعلانات لمستخدمي `pro` كميزة ضمن الاشتراك المدفوع
   (نموذج «ادفع لإزالة الإعلانات»).

## 4. عرض القيمة لكل طرف {#4-value-prop}

| الطرف | القيمة المقدّمة |
|---|---|
| **المعلِن** | وصول دقيق لجمهور متداول نشط، استهداف سلوكي فريد، قياس شفّاف، تحكّم ذاتي بالميزانية. |
| **المنصة** | مصدر دخل جديد عالي الهامش من أصول قائمة، دون تكلفة اكتساب جمهور إضافية. |
| **المستخدم** | إعلانات أقل وأكثر صلة بسياق التداول، مع شفافية وخيارات تحكّم. |

## 5. نطاق MVP مقابل المراحل اللاحقة {#5-scope}

### 5.1 ضمن نطاق MVP

| المجال | المشمول في MVP |
|---|---|
| حساب المعلِن | تسجيل/ترقية حساب مستخدم إلى معلِن، ملف شركة أساسي |
| الحملات | إنشاء/تحرير حملة، نموذج تسعير CPC/CPM، ميزانية يومية وإجمالية، جدول بدء/انتهاء |
| الإبداعات | بانر صورة + بطاقة أصيلة (Native)، عنوان/نص/CTA/رابط، نسخة لكل لغة |
| الاستهداف | الدولة، اللغة، الخطة (free/pro)، اهتمام سلوكي مبسّط (استراتيجية/مستوى مخاطرة) |
| أماكن العرض | بانر أعلى اللوحة + بطاقة ضمن قائمة المتداولين |
| الدفع | محفظة مسبقة الدفع، شحن عبر Stripe Checkout، خصم آلي للإنفاق |
| التتبّع | الظهور القابل للمشاهدة + النقر، أحداث موقّعة |
| التقارير | لوحة معلِن أساسية (ظهور، نقرات، CTR، إنفاق، CPC) |
| الإدارة | طابور مراجعة، اعتماد/رفض مع سبب، لوحة دخل أساسية |
| الامتثال | تنبيه مخاطر إلزامي على الإعلانات المالية، سياسة محتوى مبدئية |

### 5.2 خارج نطاق MVP (مراحل لاحقة)

- مزاد تنافسي متعدّد المزايدين (Second-Price Auction).
- نموذج CPA وتتبّع التحويلات عبر Postback/Pixel.
- إعادة الاستهداف (Retargeting) والجماهير المخصّصة (Custom Audiences).
- التحسين الآلي وتوليد الإبداعات بالذكاء الاصطناعي.
- واجهة API عامة للمعلنين، وتكاملات Programmatic خارجية.
- ضبط الوتيرة المتقدّم (Pacing) وحدّ التكرار عبر الجلسات (Frequency Capping) المتقدّم.
- الهجرة إلى PostgreSQL + Redis للعدّادات والوتيرة.

### 5.3 خارج النطاق نهائياً (Non-goals)

- شبكة إعلانات خارجية تخدم مواقع الغير (المنصة ناشر لمخزونها فقط).
- بيع بيانات المستخدمين لأطراف ثالثة (الاستهداف يتم داخلياً دون تصدير بيانات شخصية).

## 6. مؤشّرات النجاح (KPIs) {#6-kpis}

### 6.1 المؤشّر الشمالي (North Star)

**الإيراد الإعلاني لكل 1000 جلسة (Revenue per 1000 Sessions / RPM)** — يوازن بين تحقيق الدخل
وكثافة الإعلانات وجودة الاستهداف في رقم واحد.

### 6.2 مؤشّرات حسب المحور

| المحور | المؤشّر | الهدف المبدئي |
|---|---|---|
| **الدخل** | RPM، إجمالي الإيراد الشهري، eCPM | نمو شهري مطّرد |
| **العرض (Supply)** | معدّل الملء (Fill Rate) | > 80% بعد توفّر طلب كافٍ |
| **الطلب (Demand)** | عدد المعلنين النشطين، معدّل بقائهم | احتفاظ شهري > 60% |
| **الأداء للمعلن** | CTR، ROAS، CPC | CTR أعلى من متوسّط السوق بفضل الصلة |
| **الجودة والامتثال** | نسبة الإعلانات المعتمدة، زمن المراجعة | > 95% التزام بالسياسة |
| **حارس التجربة (Guardrail)** | معدّل تخلّي المستخدمين، شكاوى الإعلانات | **عدم تدهور** مقارنةً بخط الأساس |

> **مبدأ حاكم:** أي ارتفاع في الدخل يأتي على حساب «حارس التجربة» يُعدّ فشلاً لا نجاحاً.

## 7. مبادئ التصميم والحواجز الواقية {#7-principles}

1. **تجربة المستخدم أولاً (UX-First):** حدّ أقصى صارم لكثافة الإعلانات لكل صفحة/جلسة؛ لا إعلانات
   تعترض الإجراءات الحرجة (تنفيذ نسخ، إيداع).
2. **الصلة قبل الحجم (Relevance over Volume):** إعلان واحد عالي الصلة أفضل من ثلاثة عامّة.
3. **الشفافية:** كل إعلان يحمل وسم «مُموّل/Sponsored» واضحاً؛ وللمستخدم خيار إيقاف التخصيص.
4. **الامتثال أولاً (Compliance-by-Default):** الإعلانات المالية لا تُنشر إلا بعد مراجعة وتنبيه مخاطر.
5. **القياس المدمج:** كل ميزة تُطلق خلف تتبّع قابل للقياس (لا قرار بلا بيانات).
6. **التدهور اللطيف (Graceful Degradation):** فشل محرّك الإعلانات لا يُعطّل وظائف المنصة الأساسية —
   مكان العرض ببساطة يبقى فارغاً.
