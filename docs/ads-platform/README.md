## 1. الملخص التنفيذي

هذه الوثيقة تصف خطة بناء **منصة إعلانات مستقلة (Standalone Ad Platform)** — منتج قائم بذاته يمكّن المعلِنين من إنشاء حملات إعلانية، استهداف الجمهور، تمويل حساباتهم، ومراقبة الأداء، مع لوحة إدارية مركزية لإدارة المستخدمين والمحتوى ومكافحة الاحتيال.

> ملاحظة معمارية: على عكس الخطة السابقة التي كانت **مدمجة** كوحدة داخل منصة TechPioneers، هذه المنصة **مستقلة** — لها قاعدة بيانات، نطاق، ومصادقة خاصة بها، ويمكن أن تتكامل لاحقاً مع منصات أخرى عبر API بدلاً من أن تكون جزءاً منها.

تتمحور المنصة حول خمس ركائز:

| # | الركيزة | الوصف المختصر |
|---|---------|----------------|
| 1 | **صفحة الهبوط** (Landing Page) | واجهة عامة لجذب المعلنين وتحويلهم إلى مسجَّلين. |
| 2 | **لوحة المعلِن** (Advertiser Dashboard) | إنشاء وإدارة الحملات، الاستهداف، ومتابعة الأداء. |
| 3 | **المحفظة** (Wallet) | شحن الرصيد، الدفع، السحب، وأمان البيانات المالية. |
| 4 | **التقارير** (Reports) | تحليلات أداء قابلة للتخصيص (نقرات، تحويلات، CPA). |
| 5 | **لوحة المدير** (Admin Panel) | إدارة المستخدمين، مراقبة الأنشطة، إدارة المحتوى والإشعارات. |

## 3. المسرد (Glossary)

| المصطلح | التعريف |
|---------|---------|
| **المعلِن (Advertiser)** | المستخدم الذي ينشئ حملات وينفق رصيداً للوصول إلى الجمهور. |
| **الناشر (Publisher)** | الموقع/التطبيق الذي يعرض الإعلانات (مرحلة لاحقة). |
| **الحملة (Campaign)** | الحاوية العليا: الهدف، الميزانية، الجدولة. |
| **المجموعة الإعلانية (Ad Group / Ad Set)** | داخل الحملة: تجمع الاستهداف والمزايدة. |
| **الإعلان (Creative/Ad)** | الأصل المعروض: صورة/نص/فيديو + رابط وجهة. |
| **الانطباع (Impression)** | عرض واحد للإعلان للمستخدم. |
| **النقرة (Click)** | نقر المستخدم على الإعلان. |
| **التحويل (Conversion)** | إجراء مرغوب بعد النقر (تسجيل، شراء…). |
| **CPC / CPM / CPA** | التكلفة لكل نقرة / لكل ألف ظهور / لكل تحويل. |
| **CTR** | معدل النقر = النقرات ÷ الانطباعات. |
| **المزايدة (Bid)** | أقصى مبلغ يدفعه المعلن لكل نقرة/ظهور. |
| **الرصيد (Balance)** | المبلغ المدفوع مسبقاً في محفظة المعلن. |
| **التقييد الترددي (Frequency Cap)** | أقصى عدد مرات عرض إعلان لنفس المستخدم. |
| **الوتيرة (Pacing)** | توزيع إنفاق الميزانية على مدار الفترة. |

## 4. المكدّس التقني الموصى به

اخترنا مكدّساً يحافظ على التناسق مع خبرة الفريق الحالية (TypeScript عبر الواجهتين) مع قابلية للتوسّع:

| الطبقة | الاختيار | السبب |
|--------|----------|-------|
| الواجهة الأمامية | **React + Vite + TypeScript + Tailwind** | متوافق مع خبرة الفريق، أداء عالٍ، دعم i18n عربي/إنجليزي (RTL). |
| الخلفية | **Node.js + Express + TypeScript** | نفس لغة الواجهة، نضج النظام البيئي. |
| قاعدة البيانات | **PostgreSQL** (بدلاً من SQLite) | الإعلانات تتطلب كتابات متزامنة عالية وتجميعات تحليلية؛ Postgres يدعم JSONB، الفهرسة المتقدمة، والمعاملات الموثوقة. |
| التحليلات | **جدول أحداث + تجميع دوري** (مرحلة أولى)، ثم **ClickHouse/المستودع** (مرحلة توسّع) | فصل حِمل الكتابة التحليلي عن البيانات التشغيلية. |
| الكاش/الطوابير | **Redis** | تقييد ترددي، عدّادات الميزانية اللحظية، طوابير المهام. |
| المدفوعات | **Stripe** (أساسي) + قابلية إضافة PayPal/مزود محلي | محافظ، مدفوعات مسبقة، Webhooks موثوقة. |
| المصادقة | **JWT** قصير العمر + Refresh Tokens | اتساق مع البنية الحالية. |
| التخزين | **S3-compatible** (الأصول الإعلانية) | رفع الصور/الفيديو. |
| الاستضافة | **Render / Fly.io / Railway** (مبدئياً) | بساطة النشر، متوافق مع `render.yaml` الموجود. |

> القرار الأهم: **الانتقال من SQLite إلى PostgreSQL**. منصة الإعلانات حِملها كتابي تحليلي مكثّف (انطباعات/نقرات بمعدّلات عالية)، وSQLite لا يناسب التزامن العالي في الإنتاج.

## 5. نطاق الإصدار الأول (MVP)

**داخل النطاق:**
- صفحة هبوط + تسجيل/دخول المعلنين.
- إنشاء حملة بسيطة: هدف (نقرات)، ميزانية يومية/إجمالية، جدولة.
- إعلان من نوع صورة + نص + رابط وجهة.
- استهداف أساسي: الموقع الجغرافي + اللغة + الجهاز.
- نموذج تسعير **CPC** فقط.
- محفظة بشحن عبر Stripe (مدفوع مسبقاً).
- تتبّع الانطباعات والنقرات + لوحة أداء أساسية.
- لوحة مدير: مراجعة/اعتماد الإعلانات، إدارة المستخدمين.

**خارج النطاق (مراحل لاحقة):**
- CPM/CPA، المزايدة في الوقت الحقيقي (RTB)، شبكة ناشرين.
- العملات الرقمية، السحب الآلي للأرباح.
- الاستهداف بالاهتمامات/إعادة الاستهداف (Retargeting).
- تحسين الحملات بالذكاء الاصطناعي.

## 6. مؤشرات النجاح (KPIs)

| المؤشر | الهدف المبدئي |
|--------|----------------|
| معدل تحويل صفحة الهبوط (زائر ← مسجّل) | ≥ 5% |
| زمن إنشاء أول حملة | ≤ 10 دقائق |
| دقة احتساب الإنفاق مقابل الرصيد | انحراف < 1% |
| زمن استجابة قرار عرض الإعلان | < 100ms (p95) |
| نسبة الإعلانات المرفوضة بسبب المحتوى | تتبَّع كمقياس جودة |

## 7. المبادئ التوجيهية

1. **الدقة المالية أولاً:** كل قرش يُنفق يجب أن يُحتسب ويُطابق الرصيد بدقة.
2. **منع الإنفاق الزائد:** لا يُعرض إعلان إذا نفد الرصيد أو الميزانية.
3. **حماية المستخدم النهائي:** مراجعة محتوى الإعلانات قبل النشر.
4. **الخصوصية:** جمع الحد الأدنى من البيانات والامتثال (GDPR-ready).
5. **قابلية القياس:** تصميم خط أحداث يتحمّل النمو من اليوم الأول.
