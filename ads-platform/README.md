# سكافولد MVP — منصّة الإعلانات المستقلة

نموذج أولي قابل للتشغيل للمرحلة 1 (راجع `../docs/ads-platform/` للخطة الكاملة).
مكدّس مطابق لخبرة الفريق: **Express + TypeScript + SQLite + JWT**، مع واجهة ثابتة عربية (RTL).

## ما المُنفَّذ في هذا السكافولد
- صفحة هبوط عربية (`/`) مع دعوات فعل وتصميم متجاوب.
- تسجيل/دخول المعلنين (`/api/auth/register`, `/api/auth/login`) عبر JWT + bcrypt.
- محفظة بنموذج دفتر الأستاذ (`/api/wallet`, `/topup`, `/transactions`).
- حملات أساسية (`/api/campaigns`) مع حاجز أمان: لا إطلاق دون رصيد كافٍ.
- إعلانات/أصول (`/api/campaigns/:id/ads`) مع تحقق من رابط الوجهة (https).
- **محرك العرض** (`GET /api/serve`): يختار أعلى مزايدة ضمن المؤهلين
  (حملة نشطة + رصيد كافٍ + ضمن الميزانية + استهداف مطابق)، يسجّل انطباعاً،
  ويعيد رابط نقر موقّعاً (HMAC).
- **تتبّع النقر** (`GET /api/serve/click/:adId`): يتحقق من التوقيع، يخصم CPC
  ذرّياً، يوقف الحملة عند نفاد الرصيد/الميزانية، ثم يعيد التوجيه للوجهة.
- **التقارير** (`GET /api/reports`): انطباعات/نقرات/CTR/إنفاق/CPC فعلي لكل حملة.
- لوحة معلِن (`/app.html`): الرصيد، الحملات، إضافة إعلان، التقارير، ومعاينة عرض حي.

### تسهيلات المعلِن
- **رصيد ترحيبي** تلقائي عند التسجيل (`bonus` بقيمة 10.00) — ابدأ فوراً بلا شحن.
- **الشحن التلقائي** (`PUT /api/wallet/settings`): عند نزول الرصيد دون حدٍّ
  يضيف النظام شحنة تلقائياً (يُحاكي خصم وسيلة الدفع المحفوظة في الإنتاج).
- **قوالب حملات جاهزة** (`GET /api/templates`, `POST /api/templates/:key/use`):
  أنشئ حملة مهيّأة بنقرة واحدة.
- **إطلاق أيسر**: يكفي رصيد لبدء الحملة (نقرة واحدة) بدل الميزانية الكاملة
  مقدماً؛ يوقف النظام الحملة تلقائياً عند نفاد الرصيد أو بلوغ الميزانية.
- **رفع صور الإعلانات**: `POST /api/uploads` (png/jpeg/webp/gif حتى 2MB)
  يحفظ الصورة ويعيد رابطها؛ تظهر في معاينة العرض الحي وطابور مراجعة المدير.
  (تخزين محلي في `uploads/`؛ الإنتاج ينتقل إلى S3 — راجع `docs/ads-platform/06`.)

### لوحة المدير (`/admin.html`)
- **مراجعة الإعلانات**: الإعلانات الجديدة تبدأ `pending` ولا تُعرض إلا بعد
  الاعتماد (`GET /api/admin/ads/review`, `POST /api/admin/ads/:id/decision`).
- **إدارة المستخدمين**: قائمة بالأرصدة، وتعليق/تفعيل الحسابات
  (التعليق يوقف حملات المستخدم ويمنع دخوله) — `GET /api/admin/users`,
  `PATCH /api/admin/users/:id`.
- **نظرة عامة**: عدد المعلنين، الحملات النشطة، الإعلانات المعلّقة، إجمالي
  الإنفاق والشحن (`GET /api/admin/overview`).
- **سجل تدقيق**: كل قرار إداري يُسجَّل في `audit_logs`.
- حساب المدير يُنشأ تلقائياً عند الإقلاع من `ADMIN_EMAIL`/`ADMIN_PASSWORD`.

## التشغيل محلياً
```bash
cd ads-platform
cp .env.example .env      # عدّل JWT_SECRET و فعّل ALLOW_DEV_TOPUP=1 للتجربة
npm install
npm run dev               # http://localhost:4000
```
الصفحات: `/` صفحة الهبوط · `/app.html` لوحة المعلِن · `/admin.html` لوحة المدير.

## النشر على Render (رابط عام)
المستودع يحوي `render.yaml` في الجذر مهيّأً لنشر هذه المنصة:
1. في Render: **New → Blueprint**، واربط هذا المستودع واختر فرع
   `claude/ads-platform-planning-goU2p`.
2. Render يقرأ `render.yaml` تلقائياً ويُنشئ خدمة `ads-platform`.
3. اضبط `ADMIN_EMAIL` و `ADMIN_PASSWORD` (للدخول إلى `/admin.html`).
4. بعد أول نشر، انسخ رابط الخدمة وضعه في `APP_URL`.
5. (اختياري) أضف `STRIPE_SECRET_KEY` و `STRIPE_WEBHOOK_SECRET` للمدفوعات
   الحقيقية، واجعل `ALLOW_DEV_TOPUP=0`.

> بديل يدوي: **New → Web Service** مع **Root Directory = `ads-platform`**،
> Build: `npm install && npm run build`، Start: `npm start`.

> ملاحظة بيانات: القرص على Render مؤقت، فبيانات SQLite تُعاد عند كل نشر
> (حساب المدير يُعاد إنشاؤه تلقائياً من متغيرات البيئة). للإنتاج الفعلي
> انتقل إلى PostgreSQL أو اربط قرصاً دائماً (راجع `docs/ads-platform/06`).

## المدفوعات (Stripe)
- **الشحن** عبر **Stripe Checkout**: `POST /api/wallet/topup` يعيد `checkoutUrl`
  لصفحة دفع مستضافة. الرصيد لا يُضاف من رد المتصفح بل عبر **الـ Webhook**.
- **الـ Webhook**: `POST /api/webhooks/stripe` يتحقق من التوقيع (جسم خام) ويضيف
  الرصيد عند `checkout.session.completed` بشكل **idempotent** (مرجع = `session.id`)
  فلا يتكرر الشحن عند إعادة إرسال الحدث.
- طبقة المدفوعات معزولة في `src/payments.ts` خلف واجهة واحدة، فيسهل إضافة مزوّد
  آخر لاحقاً دون لمس منطق المحفظة (راجع `docs/ads-platform/03`).
- **التطوير بلا Stripe**: اضبط `ALLOW_DEV_TOPUP=1` لشحن مباشر تجريبي؛ ومن دون
  Stripe ولا هذا العلم يعيد `topup` رمز 503.

### إعداد Stripe
```bash
STRIPE_SECRET_KEY=sk_live_...      # أو sk_test_...
STRIPE_WEBHOOK_SECRET=whsec_...    # من لوحة Stripe أو stripe-cli
APP_URL=https://your-domain        # لروابط النجاح/الإلغاء
# اختبار محلي:  stripe listen --forward-to localhost:4000/api/webhooks/stripe
```

## ملاحظات
- **المبالغ بالسنت** (أعداد صحيحة) لتفادي أخطاء الفاصلة العائمة.
- SQLite للتطوير؛ الإنتاج ينتقل إلى **PostgreSQL** (راجع `docs/ads-platform/06`).

## مكافحة الاحتيال (Anti-fraud)
نقرات أحادية الاستخدام وتقييد ترددي لحماية ميزانية المعلن (راجع `docs/ads-platform/04,05`):
- **nonce أحادي الاستخدام**: كل رابط نقر يحمل nonce موقّعاً يُسجَّل عند الاستخدام؛
  إعادة تشغيل الرابط تُرفض (`replay`) دون خصم.
- **تقييد ترددي**: أقصى نقرات مدفوعة لكل مستخدم/إعلان ضمن نافذة زمنية
  (`FRAUD_MAX_CLICKS`, `FRAUD_WINDOW_MIN`)؛ ما زاد يُرفض (`frequency`).
- **تصفية البوتات**: وكلاء معروفون/غياب User-Agent → إعادة توجيه دون خصم (`bot`).
- **تحقق التوقيع**: رابط مزوّر/منتهٍ → 400 (`bad_signature`).
- المرفوضات تُسجَّل في `fraud_events` وتظهر في لوحة المدير
  (`GET /api/admin/fraud`, عدّاد «نقرات محجوبة»). في كل الحالات المستخدم يُعاد
  توجيهه للوجهة لكن **لا يُخصم** من المعلن.

## غير مُنفَّذ بعد (مراحل لاحقة)
رفع الأصول الفعلي (S3)، عدّادات Redis اللحظية والوتيرة (Pacing)، الاستهداف
المتقدم (العمر/الاهتمامات/إعادة الاستهداف)، استرداد الرصيد عبر Stripe، وكشف
الاحتيال المتقدم (بصمة الجهاز/التعلّم) — كلها موصّفة في وثائق التخطيط.
