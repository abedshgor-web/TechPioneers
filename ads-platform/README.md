# سكافولد MVP — منصّة الإعلانات المستقلة

نموذج أولي قابل للتشغيل للمرحلة 1 (راجع `../docs/ads-platform/` للخطة الكاملة).
مكدّس مطابق لخبرة الفريق: **Express + TypeScript + SQLite + JWT**، مع واجهة ثابتة عربية (RTL).

## ما المُنفَّذ في هذا السكافولد
- صفحة هبوط عربية (`/`) مع دعوات فعل وتصميم متجاوب.
- تسجيل/دخول المعلنين (`/api/auth/register`, `/api/auth/login`) عبر JWT + bcrypt.
- محفظة بنموذج دفتر الأستاذ (`/api/wallet`, `/topup`, `/transactions`).
- حملات أساسية (`/api/campaigns`) مع حاجز أمان: لا إطلاق دون رصيد كافٍ.
- إعلانات/أصول (`/api/campaigns/:id/ads`) مع تحقق من رابط الوجهة (https).
- **محرك العرض** (`GET /api/serve`): يختار أعلى مزايدة ضمن المؤهلين
  (حملة نشطة + رصيد كافٍ + ضمن الميزانية + استهداف مطابق)، يسجّل انطباعاً،
  ويعيد رابط نقر موقّعاً (HMAC).
- **تتبّع النقر** (`GET /api/serve/click/:adId`): يتحقق من التوقيع، يخصم CPC
  ذرّياً، يوقف الحملة عند نفاد الرصيد/الميزانية، ثم يعيد التوجيه للوجهة.
- **التقارير** (`GET /api/reports`): انطباعات/نقرات/CTR/إنفاق/CPC فعلي لكل حملة.
- لوحة معلِن (`/app.html`): الرصيد، الحملات، إضافة إعلان، التقارير، ومعاينة عرض حي.

### تسهيلات المعلِن
- **رصيد ترحيبي** تلقائي عند التسجيل (`bonus` بقيمة 10.00) — ابدأ فوراً بلا شحن.
- **الشحن التلقائي** (`PUT /api/wallet/settings`): عند نزول الرصيد دون حدٍّ
  يضيف النظام شحنة تلقائياً (يُحاكي خصم وسيلة الدفع المحفوظة في الإنتاج).
- **قوالب حملات جاهزة** (`GET /api/templates`, `POST /api/templates/:key/use`):
  أنشئ حملة مهيّأة بنقرة واحدة.
- **إطلاق أيسر**: يكفي رصيد لبدء الحملة (نقرة واحدة) بدل الميزانية الكاملة
  مقدماً؛ يوقف النظام الحملة تلقائياً عند نفاد الرصيد أو بلوغ الميزانية.

### لوحة المدير (`/admin.html`)
- **مراجعة الإعلانات**: الإعلانات الجديدة تبدأ `pending` ولا تُعرض إلا بعد
  الاعتماد (`GET /api/admin/ads/review`, `POST /api/admin/ads/:id/decision`).
- **إدارة المستخدمين**: قائمة بالأرصدة، وتعليق/تفعيل الحسابات
  (التعليق يوقف حملات المستخدم ويمنع دخوله) — `GET /api/admin/users`,
  `PATCH /api/admin/users/:id`.
- **نظرة عامة**: عدد المعلنين، الحملات النشطة، الإعلانات المعلّقة، إجمالي
  الإنفاق والشحن (`GET /api/admin/overview`).
- **سجل تدقيق**: كل قرار إداري يُسجَّل في `audit_logs`.
- حساب المدير يُنشأ تلقائياً عند الإقلاع من `ADMIN_EMAIL`/`ADMIN_PASSWORD`.

## التشغيل
```bash
cd ads-platform
cp .env.example .env      # عدّل JWT_SECRET
npm install
npm run dev               # http://localhost:4000
```

## ملاحظات
- **المبالغ بالسنت** (أعداد صحيحة) لتفادي أخطاء الفاصلة العائمة.
- `POST /api/wallet/topup` تجريبي فقط؛ في الإنتاج يُضاف الرصيد عبر Webhook من Stripe.
- SQLite للتطوير؛ الإنتاج ينتقل إلى **PostgreSQL** (راجع `docs/ads-platform/06`).

## غير مُنفَّذ بعد (مراحل لاحقة)
رفع الأصول الفعلي (S3)، لوحة المدير ومراجعة الإعلانات، تكامل Stripe الفعلي
عبر Webhook، إزالة تكرار النقر/مكافحة الاحتيال المتقدمة، التقييد الترددي
والوتيرة، عدّادات Redis اللحظية، والاستهداف المتقدم — كلها موصّفة في وثائق التخطيط.

> ملاحظة أمنية (MVP): روابط النقر الموقّعة غير أحادية الاستخدام بعد، لذا يمكن
> إعادة تشغيلها خلال مدة الصلاحية. الإنفاق يبقى محدوداً برصيد المعلن وميزانيته،
> لكن إزالة التكرار وكشف الاحتيال مطلوبة قبل الإنتاج (راجع `docs/ads-platform/04`).
